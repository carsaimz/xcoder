# Internationalization (i18n)

XCoder ships **43 locales**: complete dictionaries for English (`en`), Portuguese (`pt`)
and Spanish (`es`), plus generated stubs for 40 more languages that fall back to English
until translated.

## How it works

- Source of truth: `src/lang/en.ts` — a flat `'key': 'value'` dictionary with `{var}` placeholders.
- Complete locales: `src/lang/pt.ts`, `src/lang/es.ts`.
- Generated stubs: `src/lang/gen/<code>.ts` — registered automatically; missing keys fall
  back to `en` at runtime (`t()` never throws).
- `src/lang/gen/index.ts` is **generated** — do not edit by hand.

## Tooling (`utils/lang-cli.mjs`)

```bash
npm run gen:locales                      # create missing stubs + regenerate gen/index.ts
node utils/lang-cli.mjs --check          # verify en/pt/es have identical key sets (CI gate)
node utils/lang-cli.mjs --missing de     # list keys still missing from a locale
```

The CI workflow runs `--check` on every push — keep en/pt/es in sync or the build goes red.

## Runtime API

```js
import { t, setLocale, getLocale, listLocales, registerLocale } from '@/lib/i18n';

t('editor.saved', { path: 'a.ts' });   // "Saved a.ts"
setLocale('pt');
listLocales();                          // [{code:'de', name:'de'}, …]
registerLocale('kri', { 'ok': 'ɔk' }); // plugins can add locales at runtime
```

Locale selection order at boot: stored setting → navigator languages → `en`.
Changing the locale persists the setting and reloads the chrome so every rendered string
picks up the new language.

## Adding a translation

1. Check what's missing: `node utils/lang-cli.mjs --missing fr`
2. Translate in `src/lang/gen/fr.ts` (copy the key list from `en.ts`).
3. If the language is not stubbed yet, add its code to `ALL_LOCALES` in
   `utils/lang-cli.mjs` and run `npm run gen:locales`.
4. `npm run gen:locales` regenerates `gen/index.ts`.
5. Open a PR titled `i18n: add French translation` — the labeler tags it `i18n`.

Please translate complete files; a half-translated locale silently mixes languages.
For locale naming use ISO codes (`pt`, `zh-TW`, `pt-BR`).

## Key naming

`<domain>.<name>`: `header.*`, `tree.*`, `editor.*`, `terminal.*`, `palette.*`,
`settings.*`, `providers.*`, `agent.*`, `plugins.*`, `dialog.*`, `ws.*`, `git.*`.
Interpolation uses `{name}` placeholders — keep them verbatim in translations.
