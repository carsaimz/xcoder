# Internationalization (i18n)

XCoder ships a 43-locale scaffold with **pt, en and es fully translated** and
40 placeholder skeletons ready for contributions.

---

## How it works

- Locale files: `src/lang/<code>.json` — **flat key/value maps**, copied to
  `www/lang/` at build time and fetched at runtime.
- Lookup chain: **requested locale → pt → en → the key itself** (the UI never
  shows a blank string).
- `{var}` placeholders are interpolated by `i18n.t(key, vars)`.
- The active language is a setting (`lang`); changing it reloads the UI.
- `__meta__` inside each file tracks `{ code, status: complete|placeholder }`
  and is ignored by the runtime.

Placeholders currently mirror the English values, so untranslated locales
simply render English until contributors fill them in.

---

## CLI

```bash
pnpm run lang -- add <code> [name]   # scaffold a new locale from en.json
pnpm run lang -- remove <code>       # delete a locale file (en is protected)
pnpm run lang -- search <term>       # search keys and values
pnpm run lang -- update              # diff every locale against en.json
pnpm run lang -- stats               # translation coverage table
```

Examples:

```bash
pnpm run lang -- add de German
pnpm run lang -- search delete
pnpm run lang -- update
pnpm run lang -- stats
```

`update` is the translator's worklist: it lists every **missing** key per
locale (and obsolete keys worth pruning).

## Regenerating the 40 skeletons

`utils/generate-locales.js` recreates placeholder files for the supported
locale list without touching existing translations:

```bash
node utils/generate-locales.js           # skip existing files
node utils/generate-locales.js --force   # overwrite placeholders too
```

Supported codes live in the `SUPPORTED` array of that script — add a code
there when introducing a new locale.

---

## Translating — ground rules

1. Translate **values only**; keys and `{placeholders}` stay untouched.
2. Keep placeholders intact and in the natural position for the target
   language: `"Delete \"{name}\"?"` → `"Eliminar \"{name}\"?"`.
3. Set `__meta__.status` to `"complete"` when a locale reaches 100 %.
4. Keys are namespaced by area (`dialog.*`, `tree.*`, `settings.*`,
   `palette.*`, `cmd.*`, `editor.*`, `plugins.*`) — keep new keys consistent
   with the area they belong to.
5. Run `pnpm run lang -- update` before opening a PR; CI fails on missing keys
   in locales flagged `complete`.

## For plugin authors

Plugins ship their own strings and are free to use any i18n strategy. A simple
pattern consistent with the app:

```js
const lang = xcoder.require('settings').get('lang');
const dicts = { en: { hi: 'Hello' }, pt: { hi: 'Olá' } };
const t = (k) => dicts[lang]?.[k] ?? dicts.en[k];
```
